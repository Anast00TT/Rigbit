# Rigbit: состояние проекта

Обновлено: 31.10.2026 (локально, проверка на LDPlayer).

## Как собрать и проверить
- В облаке (Linux): `bash tools/test.sh`; скриншоты через xvfb работают (софтверный GL):
  `xvfb-run -a -s "-screen 0 1440x3200x24" tools/godot/Godot_v4.7.2-stable_linux.x86_64 --path rigbit --rendering-driver opengl3 --quit-after 900 -- --shot=/tmp/x.png --size=720x1560 --scale=2 --demo --lang=ru`
  После правки `locale/strings.csv` перед скриншотом нужен `--import` (его делает test.sh).
- Тесты ядра: `powershell -File tools\test.ps1` (любая ошибка скрипта = провал)
- Скриншоты на компе: `powershell -File tools\shots.ps1 имя "--size=720x1560 --scale=2 --demo --demo_rig --tool=pose --mode=1 --pose"`
- APK + установка на LDPlayer + скриншот: `powershell -File tools\emu.ps1 -Build -Shot имя` (adb самого LDPlayer, устройство ищется само)
- Готовый APK: `build\rigbit-debug.apk`

## Сделано (ядро, всё под тестами)
- Документ, undo/redo на командах (жест = один шаг), сохранение .rigbit (zip: JSON + PNG, версия формата, миграции), автосохранение
- Импорт PNG/JPG/WebP и **PSD/PSB** (слои, группы, имена, прозрачность, режимы наложения, скрытые слои)
- **Автосетка** по альфе (контур, упрощение, constrained Delaunay, плотность), ручная правка точек
- **Кости**: иерархия, rest-поза как в Moho, удаление и смена родителя без сдвига
- **Веса**: до 4 костей на вершину, «к кости», автовеса, кисть весов (с нажимом стилуса), перенос весов при пересборке сетки
- **Скиннинг** (linear blend), в риге слои не пересчитываются
- **Анимация**: ключи на кости/слои/пины/ползунки, 6 интерполяций (линейная, плавная, разгон, торможение, ступенька, отскок), сдвиг/удаление ключей
- **IK**: 2 кости аналитически (локоть не перещёлкивается), длиннее FABRIK
- **Пины + ARAP** (Puppet Warp): ленточный Холецкий, ~5 мс на 300 вершин на ПК
- **Констрейны**: предел угла, независимый угол, копировать движение кости (с множителем, в т.ч. отрицательным), цель
- **Динамика**: пружина/затухание/вес, детерминированная, кеш по кадрам
- **Ползунки параметров**: ключевые формы (кости, вершины, прозрачность, свитчи), аддитивно, драйверы с защитой от циклов
- **Эффекты слоя** (шейдер): рим-лайт внутри/обводка снаружи со светом в мировых координатах, градиентный свет, цветокор

## MP4 (31.10, проверено на телефоне Насти, Xiaomi 2407FPN8EG, Mali-G720)
- `core/export/android_mp4.gd`: MediaCodec + MediaMuxer через JavaClassWrapper, без плагина. RGBA -> Bitmap -> входная Surface (lockHardwareCanvas), H.264 Baseline (без B-кадров), время кадра своё через BufferInfo.set. Результат: 576x1024, 24 fps, 48 кадров за ~0.5 с, ffprobe чистый, цвета верные
- Грабли обёртки: конструктор вложенного класса зовётся `call("MediaCodec$BufferInfo")`; поля объекта не читаются, offset/size/flags через `getClass().getField(..).getInt(obj)`; `ByteBuffer.position()` ловит перегрузку position(int); `BufferInfo.set` только через `call("set", ...)` (иначе Object.set); исключения Java: `JavaClassWrapper.get_exception()`
- Не проверено: «Сохранить» MP4 через SAF руками, 1080x1920 (TikTok) и кратность 16 на других чипах, отмена посреди записи
- **Отладка на Android:** аргументы через файл, одноразово (только debug-сборка):
  `adb shell "run-as com.rigbit.app sh -c 'echo --demo --auto=export --export_fmt=mp4 --shot=user://shot.png > files/debug_args.txt'"`, потом запуск. `--auto` работает только вместе с `--shot`
- Телефон Насти: adb id `5LAYGIJJEEMZ9TVO`. Если два adb-сервера дерутся (после `--export-debug`), убить все adb.exe и `adb start-server`

### Починено 31.10 вечером
- **Проекты не открывались при запуске**: `_set_doc(пустой)` в `_ready` затирал `settings.last_project` до проверки. Теперь последний проект открывается сам (проверено на LDPlayer: лягушка, HOME, kill, запуск)
- Кости: флаг `RbBone.hidden` (не рисуется и не ловится, веса работают; в .rigbit `"hidden": true`) и констрейн `ik_ignore` (IK-цепочка на кости обрывается, RbIK.chain_for). Гача-импорт: Clavicle1/2 скрыты + ik_ignore (плечо крутится без ключицы), Body1 ik_ignore (копчик и Body2 не тянут корпус). Тест test_gl2_import.test_ik_chains

- **Проекты в Документы/Rigbit** (`app/storage.gd`, RbStorage): при запуске проекты из user://projects переезжают туда (совпадение имён = суффикс « (2)», исходник удаляется только после проверки размера; тест test_storage). Писать в Документы Android 11+ даёт и так, но файлы прошлой установки после переустановки читаются только с «Доступом ко всем файлам» (MANAGE_EXTERNAL_STORAGE в пресете), поэтому один раз показываем окно-объяснение и открываем системный экран; при возврате (APPLICATION_RESUMED) папка подхватывается. На телефоне Насти 6 проектов переехали
- Не проверено: что после «Разрешить» `OS.get_granted_permissions()` видит MANAGE_EXTERNAL_STORAGE на HyperOS; переустановка с нуля и чтение старых файлов

### Известные ограничения
- Маска: деформация самой маски сеткой (гибкие веса, пины) не учитывается
- Эффекты слоя и маска вместе не работают (у обрезаемого слоя эффекты не применяются)
- В Анимации «Выше/Ниже» теперь двигают порядок только ключом (z), перестановка в дереве осталась в Риге
